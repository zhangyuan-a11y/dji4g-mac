# 硬件兼容

这块 App 是照着一块模块写出来的：**大疆一代 4G 模块（Baiwang QDC507）**，
里面是一颗移远（Quectel）EG25-G。它的 AT 命令集里有很大一块是移远私有的 ——
`AT+QCSQ`、`AT+QTEMP`、`AT+QNWINFO`、`AT+QENG`、`AT+QCFG="usbnet"`。同一颗
芯片换一套出厂身份就是另一个产品号，换一家厂连命令集都不一样。

所以代码里有一层**厂家档案**（`Sources/DJI4GCore/VendorProfile.swift`），把
「这条信息该问哪条命令」摊成一张表。目标是：**认得出哪一族，就用那一族的命令；
认不出来，也用 3GPP 标准命令把能拿到的拿到。**

## 怎么认

两条线索，先看 USB 厂家号，再看 `ATI` 回的那几行字。

USB 厂家号更硬 —— 那是设备自己在 USB 描述符里报的，模块改不了。`ATI` 是固件
自己写的字符串，贴牌厂会改成自己的名字（大疆这块回的是 `BAIWANG` / `QDC507`）。
两条都对不上就是**通用档**，不是失败。

| 厂家号 | 厂家 | 命令族 |
| --- | --- | --- |
| `0x2CA3` | DJI（一代 4G 模块） | 移远 |
| `0x2C7C` | Quectel | 移远 |
| `0x12D1` | Huawei | 华为 |
| `0x1E0E` | SIMCom | 芯讯 |
| `0x1199` | Sierra Wireless | 通用 |
| `0x1BC7` | Telit | 通用 |
| `0x2CB7` | Fibocom | 通用 |
| `0x1546` | u-blox | 通用 |
| `0x19D2` | ZTE | 通用 |
| `0x1E2D` | Thales | 通用 |
| `0x2DE2` | Meig | 通用 |

`ATI` 里认的词：`QUECTEL` · `QDC` · `BAIWANG` · `EG25` / `EC25` / `EC20` /
`EG06` / `EP06` / `BG95` / `BG96` / `RM500`（移远型号）· `HUAWEI` · `SIMCOM` /
`SIM7` / `SIM8` / `SIM9` / `A7670` / `A7600`。

**刻意不收 `0x05C6`**（高通那个通用厂家号）。手机插上充电时也挂在这个号下面，
收进来会让程序把客人的手机当成模块，轻则误报「模块已连接」，重则去开它的接口。
少认一个号，换的是不会认错东西。

## 每族问什么

链子是「说得最细的排前面，最通用的一步压尾」。按序试，第一个答得上话的算数。
**排在最后的那一条一定是 3GPP 标准命令**，任何一块正经模块都得答 —— 所以
最差的情况不是「一片 `--`」，而是「粗一点但准」。

| 信息 | 移远 | 华为 | 芯讯 | 通用 |
| --- | --- | --- | --- | --- |
| 信号 | `AT+QCSQ` → `AT+QENG` → `AT+CESQ` → `AT+CSQ` | `AT^HCSQ?` → `AT+CESQ` → `AT+CSQ` | `AT+CPSI?` → `AT+CESQ` → `AT+CSQ` | `AT+CESQ` → `AT+CSQ` |
| 温度 | `AT+QTEMP` | `AT^CHIPTEMP?` / `AT^TEMP?` | `AT+CPMUTEMP` | —— |
| 制式 / 频段 | `AT+QNWINFO` / `AT+QENG` | `AT^SYSINFOEX` | `AT+CPSI?` | 注册响应里的 `AcT` |
| 上网模式 | `AT+QCFG="usbnet"` | 没有 | 没有 | 没有 |
| 流量计数 | `AT+QGDCNT?` | 没有 | 没有 | 没有 |
| 选网写法 | 四参数 `AT+COPS=1,2,"46011",7` | **三参数** `AT+COPS=1,2,"46011"` | 四参数 | 四参数 |

制式那一格永远有兜底：`AT+CEREG?` 的第五格 `AcT` 是 3GPP 通用字段
（TS 27.007 §7.2），顺手就拿到了，不用额外发命令。

## 厂家私有的那几条

下面这些命令**不是每块模块都有**。发出去只会回一句 `ERROR`，客户按下去看到的
是「软件坏了」。所以每一处都先问档案，档案里空着就整段跳过：

| 命令 | 干什么 | 没有它的时候 |
| --- | --- | --- |
| `AT+QCFG="usbnet"` | 切 USB 网络模式（ECM/RNDIS） | `DataService.canSwitchUSBnetMode` 为假，「一键启用」跳过这一步，直接往下走；能不能上网交给接口实测去判 |
| `AT+QCFG="usbcfg"` | 读写 USB 功能组态（声卡位的载体） | `ModemController.canConfigureAudio` 为假，界面上的声卡开关回一句「这块模块没有这一项」 |
| `AT+QGDCNT?` | 模块自己的收发字节数 | 读数退到主机的 `NET_RT_IFLIST2`（每块网卡都有），面板上那一行照样有数 |
| `AT+COPS=1,2,…` 的参数个数 | 手动选网 | 档案里 `networkSelectAcceptsAct` 决定先发哪一套，第一条没成自动换另一条 —— 客户按这一下的时候分不出也管不着是哪家固件 |

**一条硬规矩：`AT+QCFG="usbcfg"` 不动。** 那是通话语音唯一的载体（见
`ModuleVoiceSetup`），不是通用开关 —— 加兼容层的时候别顺手把它也「通用化」。

## 加一家新模块

1. `VendorDetector.vendors` 加一行（厂家号 → 家族 → 显示名）。
2. 如果它的命令集和现有四族都不同，`VendorCatalog` 里加一份档案，
   `ModemFamily` 加一个 case。档案里 `networkSelectAcceptsAct` 记得看一眼：
   移远和芯讯吃四参数 `AT+COPS=1,2,"<号码>",7`，华为只吃三参数。
3. `SimulatedATTransport` 里补上那几条命令的应答。
4. `dji4gctl status` 那行「命令族」应该显示新名字；真机上信号、温度、频段
   三格要对得上，再跑一遍 `dji4gctl operator-set <当前那家>` 确认选网收下了。

## 认不出来的模块能用吗

能。通用档只发 3GPP 标准命令：注册、短信、通话、数据这几条主路一条都不少，
因为它们本来就走标准命令。少的是**细读数** —— 温度多半没有，频段和频点没有，
信号只剩 `AT+CSQ` 那个 0–31 的粗档。

这不是半个功能，是个明确的取舍：编一个数字出来比留 `--` 糟得多。

## 现在验过什么

- 大疆一代模块（`2CA3:4006`，QDC507）：**逐项与改动前一致** —— 温度 3 路、
  RSRP/RSRQ/SINR、FDD LTE BAND 3、频点、ECM、APN、流量计数全在。
  命令链和顺序跟原来一模一样，所以读数一个字节都没变。
- USB 身份：按**厂家**认（移远 `0x2C7C`、华为 `0x12D1`、芯讯 `0x1E0E`、
  大疆 `0x2CA3`），不认型号 —— 同一个厂家下面没见过的产品号也收，只要它在
  AT 口上答得上话。产品号只影响命令行和诊断包里显示的那个名字。
- 选网（2026-09-28 真机，QDC507 + 电信）：`operator-set 46011` 几秒收下，
  `operator-auto` 交回自动，`AT+COPS?` 读回 `0,2,"46011",7`。
- 扫网：**这块固件上不能用**（超时 + 占住 AT 口两分钟），代码里按「模块没
  回话」报，不冒充空名单。
- 模拟器：`selftest` 全过（332 项），含 USSD 解码、扫网解析、选网兜底那几条桩。
