# AT 命令表

只列代码里真的用到的命令，以及**为什么用这条**。带 ⚠️ 的是会改变模块状态、
需要重启才能生效的。

> **哪些命令是通用的、哪些是某一家私有的**：`AT+Q…`、`AT^…` 开头的基本都是
> 厂家私有，别的厂家的模块会回 `ERROR`。代码里这些命令不写死，走
> [`HARDWARE.md`](HARDWARE.md) 那张厂家档案表；本文列的是「移远那一族」的
> 那一份，也是大疆一代模块实际用的那一份。

## 身份 / 状态

| 命令 | 用途 | 备注 |
| --- | --- | --- |
| `ATI` | 型号 | 也会给出固件版本 |
| `AT+GSN` | IMEI | 用这条而不是 `AT+CGSN`，QDC507 的固件在 `GSN` 上更稳 |
| `AT+QGMR` | 固件版本 | Quectel 专用，如 `EG25GGBR07A08M2G` |
| `AT+QTEMP` | 温度 | 返回 4 个传感器，取第一个 |
| `AT+CPIN?` | SIM 状态 | `READY` / `SIM PIN` / `CME ERROR 10`（没插卡） |
| `AT+CCID` / `AT+QCCID` | ICCID | 有 `QCCID` 时优先 |
| `AT+CIMI` | IMSI | 前 5 位就是 MCC+MNC |
| `AT+CNUM` | 本机号码 | **很多卡不返回**，缺失是正常的 |

## 网络 / 信号

| 命令 | 用途 |
| --- | --- |
| `AT+CREG?` | 2G/3G 注册状态 |
| `AT+CEREG?` | LTE 注册状态 —— **优先看这条** |
| `AT+COPS?` | 当前运营商 |
| `AT+CSQ` | 信号强度（`rssi` 0–31，99 = 未知） |
| `AT+QCSQ` | 更细的信号：RSSI / RSRP / SINR / RSRQ |
| `AT+QENG="servingcell"` | 服务小区：频段、信道、RSRP、RSRQ |
| `AT+QNWINFO` | 当前接入技术（LTE / WCDMA / GSM） |
| `AT+COPS=?` | 扫一遍周围能看到的运营商。⚠️ 见下面「扫网」那一节 |
| `AT+COPS=0` | 交回自动选网（客户搬了地方要还回来） |
| `AT+COPS=1,2,"46011"` | 手动登记到某一家。移远一族吃这个三参数写法，也吃带 `,7` 的四参数版 |
| `AT+CREG?` | **判断 USSD 能不能用就看这一行** |

`AT+QENG` 的 LTE 与 WCDMA 返回字段完全不同，且 WCDMA 要给 `rssi` 取 `RSCP`
而不是 ECIO，否则信号会读成 -6 dBm。见 `ATParsers.mergeQENG`。

## 短信

初始化顺序不能乱：

```
AT+CSCS="GSM"          ← 字符集：GSM 而不是 UCS2，中文靠 PDU 里的 UCS-2 自己编
AT+CMGF=0              ← PDU 模式：中文和长短信都靠它
AT+CNMI=2,1,0,2,0      ← 新短信直接上报 +CMTI，不要存了不通知
AT+CSMP=17,167,0,0     ← 有效期等参数
```

| 命令 | 用途 |
| --- | --- |
| `AT+CPMS?` | 存储用量 —— 列表长度和「4/23」都读这里 |
| `AT+CMGL=4` | 列出全部（含已读已发）。`4` 是「所有」 |
| `AT+CMGR=<i>` | 读第 i 条 |
| `AT+CMGS=<n>` | 发送，`n` 是 **TPDU 长度**（PDU 总长减去短信中心段） |
| `AT+CMGD=<i>` / `AT+CMGD=1,4` | 删一条 / 删全部 |

`AT+CMGL=4` 的 `0/1/3` 分别表示未读/已读/已发送；发件箱里的是 SMS-SUBMIT
PDU，和收件箱的 SMS-DELIVER 结构不同，解码器两条路都要走。

**存储只有 23 个 PDU 段。** 一条中文长短信会占好几段，所以列表很容易满。

## 通话

```
AT+CLIP=1              ← 打开来电号码显示
AT+QAUDCH=0            ← 音频通道：0 = USB/蓝牙，1 = 模拟耳机（只改固件内部路由，见下）
```

| 命令 | 用途 |
| --- | --- |
| `ATD<号码>;` | 拨号。**结尾的分号不能少**，那是「语音呼叫」的意思 |
| `ATA` | 接听 |
| `ATH` | 挂断 |
| `AT+CHUP` | 挂断（有些固件 `ATH` 不管用时的兜底） |
| `AT+CLCC` | 列出当前通话：方向、状态、号码 —— **状态的可靠来源** |
| `AT+VTS="<n>"` | 通话中发 DTMF 按键 |

> `AT+QAUDCH` / `AT+QAUDMOD` / `AT+QAUDLOOP` **都不是**没有声音的原因：它们只切
> 固件内部的音频路由，而一代模块出厂时压根**没有建 DSP 语音通路**（声卡摆着，
> 通话的两个方向都是死线）。2026-09-25 六种 `QAUDMOD` 各拨一通、录音全 0，量的
> 正是这个。真正管用的是「一键安装通话语音」那五步（解锁 ADB → 装两个厂商驱动
> → 下发出厂校准 → 起 PCM 桥），见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 的
> `AudioRouting`；别照着「打开音频通道」去查没有声音的问题。

`RING` 只用来触发刷新，判断「谁在响铃」始终看 `AT+CLCC`。

**信令和声音是两件事。** 上面这些命令在 `usbcfg` 音频位为 0 的一代模块上也能
正常拨号、接听、挂断 —— 只是听不到声音，因为模块根本没把自己枚举成声卡。

要声音得**两步都做**：先把音频位打开（`usbcfg` 最后一位 / `dji4gctl voice-enable`，
见 [`NETWORKING.md`](NETWORKING.md)），再在模块上装一次语音通路
（`dji4gctl voice-provision --install`，也就是 App 里那格「通话语音」）。只做
任何一步都不出声：位开了是「有设备没通路」，通路装了是「有通路没设备」。

## 数据

| 命令 | 用途 |
| --- | --- |
| `AT+QICSGP=<ctx>` | 读 APN |
| `AT+QICSGP=<ctx>,1,"<apn>","","",0` | 写 APN（1 = IP 协议，认证 0 = 无） |
| `AT+QIACT=<ctx>` | 激活 PDP 上下文 |
| `AT+QIDEACT=<ctx>` | 拆掉 PDP |
| `AT+QGDCNT?` | 模块自己的收发计数，单位 **字节** |
| `AT+QCFG="usbnet"` | 读/写 USB 网络模式（⚠️ 重启生效） |
| `AT+QCFG="usbcfg"` | 读/写 USB 功能组态（⚠️ 重启生效） |
| `AT+CFUN=1,1` | 重启模块 |

常见 APN：电信 `CTNET`、移动 `CMNET`、联通 `UNINET`、广电 `CBNET`。
物联网卡和虚拟运营商要用开卡资料给的专用 APN。

## USSD（查话费 / 查流量）

| 命令 | 用途 |
| --- | --- |
| `AT+CUSD=1,"*100#",15` | 发一条 USSD。第三个字段是编码，15 = 默认字母表，国内三家都吃 |
| `AT+CUSD=1,"<输入>"` | 回多步菜单的下一步（和发起是**同一条**命令） |
| `AT+CUSD=2` | 取消会话 |
| `AT+CUSD=?` | 看支持哪些模式，本模块回 `+CUSD: (0-2)` |

两条容易踩的：

- **答复是主动上报，不是命令的响应。** 命令本身只回 `OK`，正文另发一条
  `+CUSD: <状态>,"<正文>",<编码>` 过来。`dji4gctl ussd` 没有轮询线程，所以
  发完要自己读那一口（`ModemController.waitForUSSD`）；App 里那条一秒一拍的
  轮询本来就在读，答案自己会到。
- **正文可能是十六进制写的 UCS2。** 国内三家查话费回来的都是这样，
  `60A87684` 就是「您的余额」。`ATParsers.decodeUSD` 只在编码字段是
  4 / 8 / 72、或者解出来真的含汉字时才当十六进制解 —— 否则「1234」这种纯
  数字余额会被解成 U+1234 那个字母。

### 这块卡上遇到的：`+CME ERROR: 30`

2026-09-28 真机，QDC507 + 中国电信：`AT+CUSD=1,"*100#",15` 回
`+CME ERROR: 30`，换 `,0` 或不带编码字段都一样。

原因不在命令上，在 `AT+CREG?` 那一行：

```
AT+CREG?    → +CREG: 0,3      ← 电路域注册被拒
AT+CEREG?   → +CEREG: 0,1     ← 分组域正常
AT+CGREG?   → +CGREG: 0,1
```

USSD 是**电路域**的业务，数据通不代表它通。30 在通话那边是「还没注册到
网络」，在 USSD 这边要换一句说法（`ATFailure.explainUSSD`），否则客户会一直
以为是自己卡没插好。

## 扫网（`AT+COPS=?`）

按标准这条要二十秒到一分钟：模块得把所有频段挨个搜一遍。本模块（QDC507
固件）实测**比标准还糟**：

- 90 秒都没回话；
- 那之后**整个 AT 口大约两分钟不应答** —— 连一句 `AT` 都没人理，App 的读数
  卡在原地。

所以：

- `scanOperators` 超时**必须和空列表分开报**。空列表是「周围确实只有这些」，
  超时是「模块正占着口子」。混成一句「没扫到」，客户只会以为是自己信号差。
- 它是「卡怎么都不注册」时的排障手段，**不要放进任何自动流程**。
- 手动选网（`AT+COPS=1,2,…`）没有这个问题，真机上几秒就回来 —— 客户要的
  那一半靠它，扫网只是给人看的。

## 其它

| 命令 | 用途 |
| --- | --- |
| `AT+CMEE=2` | 让错误变成文字（`CME ERROR: SIM not inserted`），而不是只有数字 |

模拟器另外接受 `AT`、`ATE0`、`AT&F` 这类无副作用的命令，仅为了让会话初始化
不报错 —— 程序本身不会主动发 `AT&F`（那是恢复出厂设置，会清掉 `usbcfg`）。

## 读响应时容易踩的坑

- **单位**：`AT+QGDCNT?` 是字节。按 KB 算会差 1024 倍。
- **`+QCFG` 有两套**：`usbnet` 是单值，`usbcfg` 是 10 个逗号字段，别用同一个
  解析器。
- **`AT+CSQ` 的 99** 不是「信号极强」，是「未知」。
- **`AT+CMGS` 的长度**是 TPDU 长度，不是 PDU 长度。
- **主动上报和命令响应走同一条口**：`+CMTI`、`RING` 可能插在任意两条命令
  之间，会话层必须按 `+` 前缀把它们分流出去，不能当成当前命令的响应。
